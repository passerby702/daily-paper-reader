## 摘要
文本到分子生成通常被表述为一次性序列生成问题，其中模型直接将目标描述映射为分子表示。然而，分子描述通常包含信息丰富的结构约束，违反这些约束可能改变分子的身份。这使得化学验证和纠错变得重要但尚未充分探索。为填补这一空白，我们提出了MolGVR，一个基于化学的生成器-验证器-精炼器框架。生成器推断结构证据并生成候选分子。验证器通过将描述转换为化学约束并检查候选分子是否符合这些约束来解决化学验证缺失的问题。精炼器通过修改被验证器拒绝的候选分子来解决生成失败问题。在ChEBI-20和PCDes上的实验表明，MolGVR提高了精确匹配性能。这些结果表明，将生成与可执行验证和反馈引导的精炼相结合是改进文本到分子生成的有效方法。

## Abstract
Text-to-molecule generation is typically formulated as a one-shot sequence generation problem, where a model directly maps target descriptions to molecular representations. However, molecular descriptions often contain informative structural constraints, and violating such constraints can change the molecular identity. This makes chemical verification and error correction important but underexplored. To fill this gap, we propose MolGVR, a chemistry-grounded Generator--Verifier--Refiner framework. The Generator infers structural evidence and generates candidate molecules. The Verifier addresses the lack of chemical validation by converting descriptions into chemical constraints and checking candidates against them. The Refiner addresses generation failures by revising candidates rejected by the Verifier. Experiments on ChEBI-20 and PCDes show that MolGVR improves exact-match performance. These results suggest that coupling generation with executable verification and feedback-guided refinement is an effective way to improve text-to-molecule generation.

## 2. 论文提出的方法论

### 2.1 总体框架：MolGVR（Generator–Verifier–Refiner）

MolGVR 将文本到分子生成分解为三个协调阶段：

1. **生成器（Generator）**：基于描述 `x_i`，先推断结构证据 `c_i`，再生成 K 个候选分子。
2. **验证器（Verifier）**：从描述中提取化学约束规则，用 RDKit 等确定性工具逐条检查候选分子，输出 pass 或 fail（含失败原因）。
3. **精炼器（Refiner）**：对未通过验证的候选分子，结合描述、错误分子和失败原因进行定向修正，最终与通过验证的候选合并为输出。

### 2.2 生成器（Generator）

- **骨干模型**：基于 Intern-S1-mini 进行后训练，分别在 ChEBI-20 和 PCDes 的训练集上训练。
- **SFT（监督微调）**：借鉴 MSR 方法，用 RDKit 从真实 SMILES 中提取六类结构证据：
  - 分子式
  - 最长碳链长度
  - 芳香环信息
  - 环系信息
  - 官能团
  - 手性
- 训练目标为"证据序列 + 金标准分子"的拼接序列，损失函数采用标准的自回归交叉熵：

```
L_gen_SFT = - Σ_{t} log G_θ( y*_{i,t} | x_i, y*_{i,<t} )
```

- **RL（强化学习）**：在 SFT 基础上使用 GRPO，奖励函数为：

```
r(o) = (1 - λ) * r_acc(o) + λ * r_fmt(o), λ = 0.1
```

- `r_fmt`：格式奖励，鼓励输出包含六个证据标签、`</think>` 和 `\boxed{}` 最终答案。
- `r_acc`：精确匹配奖励，直接比较 `\boxed{}` 内字符串与金标准答案的原始字符串是否一致（避免 rollout 时频繁调用 RDKit 规范化）。

### 2.3 验证器（Verifier）

- **规则提取**：使用 GPT-5.2 提示模型按预定义 JSON schema 从描述中提取可检查的结构约束，并使用**保守式规范化**（closed vocabulary），避免过度推断和误报。
- **规则类别**：
  - ChEBI-20：官能团、核心骨架/环系、元素/原子类型、元素计数、基团计数、立体化学，加上内置的无效 SMILES 检查。
  - PCDes：官能团、核心骨架/环系、元素/原子类型、元素计数、基团计数、盐/电荷状态，加上无效 SMILES。
- **确定性执行**：将提取的规则翻译为基于 RDKit 的检查代码（SMARTS 子结构匹配、原子计数、立体化学赋值、形式电荷检查等），对每个候选分子逐条执行。
- **专家审查**：规则定义和检查逻辑需经化学专家验证，只有专家确认可靠的规则才能影响 pass/fail 判定，以保证验证器的准确性。

### 2.4 精炼器（Refiner）

- 输入为"分子描述 + 被拒绝的候选分子 + 失败原因"，输出为修正后的分子。
- **两阶段 SFT**：
  - 第一阶段：用"描述 + 错误候选" → 金标准分子，训练通用修正能力。
  - 第二阶段：仅对验证器拒绝的候选，加入失败原因，训练"失败感知的定向修正"。
- 数据由生成器采样 20 个候选后构造：第一阶段得到 38,891 个实例；第二阶段得到 6,725 个实例。

## 6. 论文的主要结论与发现

- **主结果**：
  - ChEBI-20：MolGVR 的 Match 达到 **0.582**，较最强基线 ChemDFM-v1.5-8B（0.530）提升约 9.8%，并取得 MACCS/RDK/Morgan 指纹相似度最优。
  - PCDes：MolGVR 的 Match 达到 **0.500**，较 bioT5（0.455）提升约 9.9%，同样取得三种指纹相似度最优。
- **核心发现**：
  - 验证器能识别出 183/1414（ChEBI-20）和 138/1526（PCDes）个违反规则的候选。
  - 精炼器对验证器拒绝候选中约 **20%** 能修正为精确正确分子，远高于额外采样（2.7%–3.6%）。
  - 将验证与多候选采样结合（pass@5）可进一步提升 Match，说明两者互补。
  - MSR+RL 与验证-精炼（V&R）可跨骨干模型迁移，两者结合时效果最好。
- **总结观点**：将生成与可执行验证、反馈引导精炼结合起来，能够有效缓解验证-修正缺口，提高文本到分子生成的忠实度。

## 7. 优点

- **范式新颖**：从 one-shot 生成转向"生成-验证-精炼"流程，更加贴近真实药物设计中的"提出-评估-修正"工作流。
- **化学可解释性**：验证器把自然语言描述转化为可执行的化学规则（SMARTS、原子计数、立体化学检查等），而非仅依赖模型隐式判断。
- **有效纠错**：失败原因是结构化、可解释的，精炼器能据此进行定向修正，而非盲目重采样。
- **严谨的验证器设计**：通过专家审查、保守式规则提取和确定性执行，实现零误拒，减少把正确分子送入精炼器的风险。
- **充分的消融与泛化实验**：不仅验证主框架，还对 Generator 训练、验证器行为、跨模型迁移、分类别效果进行了系统分析。
- **实用性好**：推理开销增加较小（@1 增加约 39 秒，@5 增加约 79 秒），同时显著提升 Match 和结构相似度。

## 8. 不足与局限

- **指标覆盖不平衡**：在 Validity、BLEU、Levenshtein、FCD 等指标上并不总是最优，论文解释为这些指标对 SMILES 表面形式和分布对齐敏感，而非精确分子身份。
- **验证器覆盖有限**：当前规则只能覆盖部分错误类型；183/1414、138/1526 的拒绝数表明仍有很多分子级错误未被约束检查捕获。
- **依赖外部 LLM 与封闭词表**：规则提取依赖 GPT-5.2，且规范化标签为预定义闭集，无法覆盖所有可能的化学描述；提取质量直接影响验证效果。
- **过度保守**：为避免误拒，验证器只使用专家验证过的硬规则，导致召回率偏低，无法全面捕获违反描述的候选。
- **无方差与显著性分析**：主要结果均为单次评估，未报告多次运行的均值/标准差或统计检验，难以判断提升的稳定性。
- **训练数据合成依赖生成器**：Refiner 训练数据来自生成器自身采样，可能引入生成偏差；且第二阶段数据量较小（ChEBI-20 5,570 条、PCDes 1,155 条）。
- **RL 奖励简化**：加速奖励使用 raw-string 精确匹配而非 RDKit 规范化匹配，可能对合法但表示方式不同的正确分子产生惩罚，从而过高或过低估计模型能力。
- **算力报告不完整**：未报告训练总时长和能耗，难以评估整体训练成本。
- **时空局限**：论文发表于 2026 年，所对比的某些模型（如 ether0-24B、GPT-5.2 等）版本较新，结论是否适用于后续更强的模型仍需进一步验证。
