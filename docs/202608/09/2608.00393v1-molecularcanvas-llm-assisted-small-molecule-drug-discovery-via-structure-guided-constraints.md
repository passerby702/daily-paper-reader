## 摘要
小分子药物发现依赖于迭代式分子优化，化学家们在此过程中反复修改候选化合物，以平衡功效、毒性和溶解度等多重相互竞争的特性。生成式人工智能（GenAI）的最新进展通过自动提出新的分子结构或定向修改，在加速这一过程方面展现出前景。然而，现有的基于GenAI的分子设计工具与专家的真实工作流程仍不契合。具体而言，它们在指定分子结构层面修改意图方面支持有限，对模型生成的修改的透明性不足，并且缺乏与外部计算工具进行下游属性评估的集成支持。为应对这些挑战，我们引入了MolecularCanvas，一个交互式系统，使用户能够通过整合高层次目标、结构层面标注、属性约束和基于参考的偏好来迭代构建优化上下文。该上下文引导候选分子在不同分子结构中的生成。MolecularCanvas还通过为AI生成的建议提供证据来增强透明度，并通过将常用的属性评估计算工具集成到统一界面中，简化了分子评估流程。最后，一项涉及12名参与者的用户研究证明了MolecularCanvas在帮助用户优化候选分子方面的实用性和有效性。

## Abstract
Small-molecule drug discovery relies on iterative molecular optimization, where chemists repeatedly modify candidate compounds to balance multiple competing properties such as efficacy, toxicity, and solubility. Recent advances in generative AI (GenAI) have shown promise in accelerating this process by automatically proposing new molecular structures or targeted modifications. However, existing GenAI-based molecular design tools remain poorly aligned with experts' real-world workflows. Specifically, they offer limited support for specifying structure-level modification intents on molecules, provide insufficient transparency into model-generated modifications, and lack integrated support for downstream property evaluation with external computational tools. To address these challenges, we introduce MolecularCanvas, an interactive system that enables users to iteratively construct an optimization context by integrating high-level goals, structure-level annotations, property constraints, and reference-based preferences. This context guides the generation of candidate molecules across diverse molecular structures. MolecularCanvas further enhances transparency by providing evidence for AI-generated suggestions and streamlines molecular evaluation by integrating commonly used computational tools for property assessment into a unified interface. Finally, a user study with 12 participants demonstrates the usefulness and effectiveness of MolecularCanvas in helping users optimize candidate molecules.

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想

不再依赖单一的、自由形式的文本提示（free-form prompt），而是让用户通过四种互补的“意图视角”迭代构建一个结构化的“优化上下文”，并以此引导候选分子的生成：

1. **高层目标**（Goal）：以自然语言描述总体设计目标（例如“降低毒性”或“覆盖革兰氏阳性菌”）。
2. **结构级编辑意图**（Structure-level annotations）：直接在分子画布上对选定的子结构进行标注。
3. **属性偏好**（Property constraints）：通过滑块指定目标属性的期望范围。
4. **基于参考的偏好**（Reference-based preferences）：从其他分子（如先前候选或新上传的示例）中借用和标注有用的模式。

### 2.2 系统界面（六个协调面板）

| 面板 | 功能 | 对应设计需求 (DR) |
|---|---|---|
| **A. Goal Specification Panel** | 通过SMILES或文件导入起始分子，用自然语言设定高层优化目标 | DR1 |
| **B. Molecule Canvas Panel** | 集成开源分子编辑器Ketcher，支持结构级编辑；用户可标注子结构为**Anchor**（保留）、**Avoid**（避免修改），或附加**自由文本提示**（如“替换为氟原子”） | DR1 |
| **C. Property Panel** | 展示当前分子的cLogP、MW、TPSA等属性，按药物化学标准分为物化、溶解度、ADME、安全性和可开发性五类；滑块设定目标区间，同时显示当前值和前一轮值 | DR1 |
| **D. Reference Panel** | 从先前候选或上传的示例中提取结构偏好（Prefer/Avoid/自由提示），可激活或停用 | DR1 |
| **E. Candidate Panel** | 以排名卡片列表展示候选分子，每张卡片含2D结构预览、综合得分、意图满足度总结（绿色/红色高亮）和外部证据（药物数据库、生物测定、专利记录等）；支持预览、保留、拒绝或采用 | DR2、DR3、DR5 |
| **F. History Panel** | 以分支化树状结构记录分子演化轨迹，支持回溯、多版本勾选与并排比较 | DR4 |

### 2.3 计算管线（三阶段）

- **阶段一：意图形式化（Modification Intent Formulation）**
  用户界面操作被转化为机器可读的结构化规范（JSON格式），包含：(1) 待优化分子的SMILES表示；(2) 文本形式的高层目标；(3) 属性约束列表（属性名、当前值、目标区间）；(4) 结构约束列表（分子SMILES + 带原子ID注释的子结构 + 意图标签：anchor/avoid/prefer/free-form）。原子ID直接从分子编辑器中获取，无需视觉-语言模型对渲染结构进行解读。

- **阶段二：候选生成（Candidate Generation）——两阶段生成策略**
  - **Step 1 (Edit Plan Generation)**：将结构化意图发送给LLM（实验中采用GPT-4o），要求其输出显式的结构编辑操作计划（如“在位置23用F原子替换Cl原子”“在位置45添加极性基团”）。采用中间编辑计划的动机是：**高层目标与属性约束最终通过结构修改实现，可能与结构约束冲突；显式计划使得冲突可在执行前被检测和过滤**。
  - **Step 2 (Plan Execution & Validation)**：用RDKit将每个编辑操作翻译为具体分子变换（替换/添加/删除），并进行两步验证：①化学有效性检查（化合价、芳香性、环键一致性）；②去重（规范SMILES去精确重复，Morgan指纹>0.85的Tanimoto相似度去除近似重复），保持结构多样性。

- **阶段三：候选评估（Candidate Evaluation）**
  沿三个维度打分并排序，取top-k展示给用户：
  - **属性约束满足**：计算候选分子的属性，基于其落入目标区间的程度打分。
  - **结构约束满足**：检查anchor和avoid的子结构是否被尊重。
  - **化学合理性**：基于Lipinski五规则和Veber规则的违规数进行惩罚。
  高层目标和不规整的提示约束不直接打分（因缺乏可靠的事后评估指标），仅用于引导生成方向。最后从ChEMBL等数据库为每个候选检索支持性证据（相似已知化合物、药物撤市/黑盒警告、临床试验阶段、生物活性数据）——要求Tanimoto相似度≥0.8。

## 6. 主要结论与发现

### 定量结果

- **感知有效性**：13项问卷（Q1–Q13）MolecularCanvas **全部显著优于基线**（均p < 0.05），例如：
  - 高效分子设计（Q1）：4.17±0.58 vs. 2.67±1.30 (p < 0.01)
  - 证据支持评估（Q8）：3.75±0.87 vs. 2.25±1.29 (p < 0.05)
  - 追踪整体设计过程（Q11）：4.25±0.62 vs. 2.25±1.29 (p < 0.01)
- **可用性**：SUS得分72.50±10.82 vs. 基线60.83±14.16（p < 0.05），72.5分对应“良好”（good）可用性水平。
- **最终分子质量**：专家盲评中，MolecularCanvas组的分子平均得分0.73（归一化0–1）显著高于基线组的0.58（p < 0.001），ICC=0.94。
- **生成管线可靠性**：95.0%的LLM输出产生可执行编辑计划；57.0%的生成候选通过有效性与多样性过滤；91.0%的留存候选满足指定的结构约束。综合约两次生成尝试可产生一个有效、非重复、满足约束的候选。

### 定性发现（四个主题）

1. **结构级意图表达的精准性**（9/12参与者）：anchor/avoid等操作被频繁、重复地用于保留核心结构（如喹诺酮核心），替代了反复修改提示词的繁琐过程。
2. **工作台整合降低了跨平台切换成本**（8/12）：单一界面完成结构编辑、属性检查和候选评估，消除了碎片化工作流带来的认知中断。
3. **比较式决策**（10/12）：参与者倾向于通过比较候选卡片的属性变化和结构差异来决策，而非信任单一输出。
4. **非线性探索与回溯**（7/12）：历史面板支持“撤销式冒险”——用户敢于进行大胆修改（如改变核心支架），因为知道可以回溯；支持反事实推理和多分支探索。

## 7. 优点

- **结构作为一等公民的交互范式**：直接在图结构上进行标注（anchor/avoid/free-form提示），避免了自然语言描述的歧义和负载，是“结构化对象+AI辅助”交互设计的成功范例，可推广至蛋白质工程、材料科学等结构密集领域。
- **两阶段生成策略（编辑计划→执行验证）**：先让LLM生成显式编辑操作计划而非直接生成分子，使结构冲突在执行前可检测，再以RDKit保证化学有效性和结构多样性——该设计将LLM的化学知识局限与确定性化学引擎的优势结合，且验证逻辑与具体LLM无关（模型无关）。
- **证据与可追溯性**：每个候选附带结构化证据（数据库匹配、安全信号、临床试验阶段、专利信息），缓解了“AI黑盒不透明”的信任问题；历史面板将迭代过程可视化为可回溯、可比对的分支图，并天然形成“可审计的科学实验记录”。
- **工具集成而非功能堆砌**：将评估能力嵌入核心设计任务，保持工作流连续性和认知连续性，而非简单地在单一界面中组合多个不相关的功能。
- **研究方法的严谨性**：形成性研究→设计需求→系统设计→用户研究的完整闭环；专家盲评+高ICC（0.94）提升了结论可信度；定量和定性证据相互印证。

## 8. 不足与局限

- **LLM生成准确性的固有瓶颈**：LLM主要基于SMILES等文本分子表示进行推理，对于立体化学（手性中心保留/反转）、构象灵活性等复杂化学信息处理能力有限。未来的改进方向是引入多模态生成模型（分子图+3D构象+文本）。
- **2D交互的表意局限**：系统以2D分子表示为核心交互媒介，无法充分表达3D构象、与靶蛋白的结合模式或构象柔性。在2D中看似理想的修改可能在3D空间中存在位阻冲突或失去关键相互作用。论文建议未来集成分子对接和3D可视化。
- **缺少需求优先级与权衡管理**：当多个属性目标相互冲突时（如活性vs.安全性），系统不支持显式的加权或优先级设定，仅能并列呈现约束。未来需要引入权重调节和冲突可视化。
- **可扩展性不足**：系统定位为“视觉+LLM交互”的分子优化平台而非通用化学信息学平台，无法覆盖真实实验室工作流的全部多样性和演化性，需要可配置的插件集成机制。
- **评估覆盖有限**：
  - 无组件级消融实验（作者已明确承认）。
  - 无纵向研究，无法评估长期实际应用效果。
  - 任务仅覆盖抗生素优化场景，泛化性待验证。
  - 用户研究样本量较小（N=12），且未进行可重复性验证。
  - 参与者基线工具组合不统一（自由使用熟悉工具），可能引入个体工具偏好差异。
